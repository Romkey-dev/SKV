## Цель работы

Настроить Git в Debian, подключиться к GitLab по SSH и отправить историю локального репозитория в удалённый проект.

## Ход выполнения

1. Проверил Git командой `wsl -d Debian12 -- git --version`. В Debian 12 Bookworm установлена версия `2.39.5`.
2. Задал имя и email автора через `git config --global user.name` и `git config --global user.email`.
3. Создал SSH-ключ Ed25519, загрузил его в `ssh-agent` и добавил публичный ключ в профиль GitLab. При проверке командой `ssh -T git@gitlab.com` сервер ответил `Welcome to GitLab, @Romkey-dev!`.
4. Инициализировал репозиторий в `/root/hello-git` командой `git init -b main`. Добавил `README.md` с описанием проекта и сведениями об авторе.
5. Добавил [`.gitignore`](.gitignore) с правилами для системных, временных файлов и каталогов IDE. Проверил правила командой `git check-ignore`.
6. Настроил SSH-адрес `origin` и выполнил `git push -u origin main`. При отправке GitLab создал приватный проект `hello-git`.

Локальная ветка `main` отслеживает `origin/main`. Сверка через `git ls-remote` подтвердила совпадение последних коммитов. GitLab использует `main` как ветку по умолчанию. Рабочая директория чистая.

## Ответы на контрольные вопросы

1. **Что отличает распределённую СКВ от централизованной?** В распределённой СКВ у разработчика есть локальная копия истории. Можно создавать коммиты и смотреть историю без подключения к серверу. В централизованной СКВ основная история хранится на сервере, к которому клиенты обращаются для операций с ней.
2. **Зачем нужен SSH-ключ в GitLab?** GitLab проверяет, что клиент владеет приватным ключом, соответствующим публичному ключу в профиле. Это позволяет выполнять Git-операции по SSH.
3. **Чем отличаются `git add` и `git commit`?** `git add` помещает выбранную версию файла в индекс. `git commit` сохраняет содержимое индекса в истории.
4. **Что такое индекс?** Это подготовленный снимок для следующего коммита. Его можно проверить командой `git diff --staged`.
5. **Как увидеть изменения вне индекса?** `git status --short` показывает изменённые и неотслеживаемые файлы. `git diff` показывает изменения отслеживаемых файлов, которые ещё не добавлены в индекс.
6. **Зачем нужен `.gitignore`?** Он задаёт правила исключения неотслеживаемых файлов, например `*.log`, `Thumbs.db` и `.idea/`. Для файлов, которые Git уже отслеживает, эти правила сами по себе ничего не меняют.
7. **Как связать локальный и удалённый репозитории?** Добавить адрес командой `git remote add origin <SSH-адрес>`, затем отправить ветку командой `git push -u origin main`. Флаг `-u` задаёт отслеживаемую ветку.
8. **Чем отличаются `git fetch` и `git pull`?** `git fetch` скачивает обновления и обновляет ссылки на удалённые ветки. `git pull` скачивает обновления и затем интегрирует их в текущую ветку согласно настройкам.

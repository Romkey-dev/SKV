## Ответы на контрольные вопросы

1. **Что такое форк?** Серверная копия проекта, связанная с оригиналом. В форк можно отправлять свои ветки и предлагать изменения исходному проекту через MR.
2. **Чем отличаются fetch и pull?** Fetch загружает изменения и обновляет ссылки на удалённые ветки. Pull затем интегрирует изменения в текущую локальную ветку.
3. **Зачем нужен upstream?** С этого remote удобно получать актуальную историю исходного проекта. Origin обычно указывает на собственный форк.
4. **Что такое Merge Request?** Запрос на объединение изменений исходной ветки с целевой. В нём видны коммиты, diff, обсуждение и состояние проверок.
5. **Как проходит MR?** Автор отправляет ветку, открывает MR и описывает изменения. Затем проходят проверки и ревью, автор вносит правки, а пользователь с нужными правами выполняет слияние.
6. **Зачем нужно Code Review?** Проверка помогает обнаружить ошибки, оценить читаемость и согласовать правки до слияния.
7. **Как обновить форк?** Выполнить `git fetch upstream`, переключиться на `main`, интегрировать `upstream/main` и отправить результат через `git push origin main`.
8. **Что такое защищённая ветка?** Ветка, для которой проект ограничивает прямую отправку и слияние. Например, можно разрешить слияние Maintainers и запретить прямой push.
9. **Чем отличаются способы слияния?** Merge commit сохраняет исходные коммиты и связывает ветки коммитом с двумя родителями. Squash объединяет изменения ветки в один коммит. Rebase переносит коммиты на новую базу перед слиянием, меняя их хеши.
10. **Как добавить участников?** В GitLab открыть список участников проекта, выбрать приглашение, указать аккаунты и назначить роли в соответствии с их задачами.

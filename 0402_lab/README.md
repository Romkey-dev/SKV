## Контрольные вопросы

1. **Reset и revert.** Reset перемещает ссылку ветки. Revert создаёт обратный коммит.
2. **Hard reset.** Перемещает HEAD и приводит индекс и отслеживаемые рабочие файлы к целевому коммиту. Незакоммиченные правки можно потерять.
3. **Интерактивный rebase.** Позволяет менять порядок, сообщения и содержимое коммитов, объединять и исключать их.
4. **Как сохранить сообщения при объединении?** Использовать `squash` и отредактировать итоговое сообщение в редакторе.
5. **Как исправить последнее сообщение?** Выполнить `git commit --amend -m "новое сообщение"`. При этом Git создаёт заменяющий коммит с новым хешем.
6. **Риск force push.** Может заменить чужие изменения на удалённой ветке.
7. **Что даёт lease?** Git отклоняет принудительный push, если удалённая ссылка отличается от ожидаемой.
8. **Как восстановить коммит?** Найти хеш через `git reflog` и создать на нём ветку через `git branch recovery <хеш>`, пока объект сохранён.
9. **Когда выбирать команды?** Revert подходит для общей истории, reset — для локальных черновых коммитов.
10. **Почему не перебазировать общую ветку?** У уже полученных коллегами коммитов меняются адреса и расходятся копии истории.

## Ответы на контрольные вопросы

1. **Что такое ветка?** Именованная ссылка на коммит. Например, `refs/heads/main` хранит хеш вершины ветки. При новом коммите в этой ветке ссылка перемещается вперёд.
2. **Когда использовать merge и rebase?** Merge сохраняет исходные коммиты и при разошедшихся ветках создаёт коммит с двумя родителями. Rebase переносит изменения на новую базу и пересоздаёт коммиты. Merge подходит для общей истории, rebase — для подготовки своей ветки перед публикацией.
3. **Как возникает конфликт?** Git сообщает о конфликте, когда не может однозначно объединить изменения. Например, обе ветки по-разному изменили один участок файла или независимо добавили файл с одинаковым именем.
4. **Как разрешить конфликт?** `<<<<<<<` открывает первый вариант, `=======` разделяет варианты, `>>>>>>>` завершает второй. Нужно оставить согласованный текст, удалить маркеры, выполнить `git add` и завершить операцию командой `git commit` или `git rebase --continue`.
5. **Чем отличаются reset и revert?** Reset перемещает ссылку ветки и в зависимости от режима меняет индекс и рабочие файлы. Revert добавляет коммит с обратными изменениями и подходит для опубликованной истории.
6. **Что такое fast-forward?** Когда вершина текущей ветки является предком входящей, Git может просто передвинуть ссылку вперёд. Если ветки разошлись, трёхстороннее слияние учитывает обе вершины и их общего предка.
7. **Зачем нужна ветка release?** В Git Flow она позволяет подготовить версию, исправить релизные ошибки и обновить номер версии, пока в ветке разработки продолжается работа над будущими изменениями.
8. **Как отправить все ветки?** `git push --all origin`. Теги отправляются отдельно командой `git push --tags origin`.
9. **Чем опасен rebase общей ветки?** У перенесённых коммитов меняются хеши. У коллег остаются ссылки на прежнюю историю, поэтому для синхронизации понадобится отдельное согласование.
